# v0.2 read/discovery security acceptance criteria

- Status: Historical accepted baseline — evidence complete and superseded by active 1.0
- Date: 2026-07-11
- Scope: `list_workspace_files`, `read_documents`, `search_workspace_text`

## Purpose

These criteria are the mandatory security and correctness gate for the three accepted
read-only tools. They apply together with accepted v0.1 criteria, accepted ADR 0005, the
v0.2 read security-model delta, and the v0.2 tool-contract draft.

`Accepted` means the behavior is agreed; it does not mean implementation exists. Every
applicable row requires an automated assertion at the named boundary before the tools
may be described as implemented. Synthetic fixtures must be used for paths, content,
secrets, and race canaries.

## Accepted constants

Byte ceilings are inclusive. A value exactly at a ceiling can be accepted; one byte or
item beyond it must be rejected, omitted, paginated, or explicitly incomplete according
to the row below.

| Contract item                       |                      Draft value |
| ----------------------------------- | -------------------------------: |
| Caller include/exclude glob         |           1,024 UTF-8 bytes each |
| Cursor                              |                 2,048 characters |
| Raw discovery candidates            |   10,000 plus one detection slot |
| File-list page                      |       default 500; maximum 2,000 |
| Batch documents                     |                     1 through 32 |
| Batch content                       | default 256 KiB; maximum 320 KiB |
| Existing per-document returned text |                          256 KiB |
| Closed search file                  |                            2 MiB |
| Aggregate inspected search text     |                           64 MiB |
| Closed-file search reads per window |                     2 concurrent |
| Search matches                      |       default 100; maximum 1,000 |
| Context lines                       |             0 through 2 per side |
| One context snippet                 |                            4 KiB |
| Aggregate context                   |                          256 KiB |
| Complete new-tool success           |                          448 KiB |
| Existing global MCP success         |                          512 KiB |
| Discovery/search deadline           |                        5 seconds |

## Discovery and glob policy

| R2-DSC-001 | Protocol unit                    | Include/exclude strings are empty, untrimmed, absolute, backslash/NUL-containing, parent-traversing, exactly 1,024 UTF-8 bytes, and one byte larger                   | Input schemas validate them                              | Only contract-valid relative glob values through the inclusive byte ceiling are accepted; invalid values fail before IPC dispatch.                                                       |
| R2-DSC-002 | Extension host                   | Repository ignore files and `files.exclude`/`search.exclude` settings conflict with the contract default                                                              | Discovery runs with omitted `exclude`                    | Only the exact contract-owned default controls exclusion; repository/editor settings neither add nor remove candidates.                                                                  |

| R2-DSC-004 | Extension host                   | Default-generated paths and ordinary source exist                                                                                                                     | Discovery runs with `exclude: null` and a narrow include | Default exclusions are disabled, only the narrow include is considered, and candidate/byte/time/output ceilings remain unchanged.                                                        |
| R2-DSC-005 | Extension host                   | Exactly 10,000 and then 10,001 raw candidates match                                                                                                                   | Discovery runs                                           | The boundary case can be complete; cap-plus-one is used only to detect the oversized case, which is explicitly incomplete without exposing the extra candidate.                          |
| R2-DSC-006 | Extension unit and host          | A regular file, directory, device-like entry where supported, internal symlink alias, external symlink escape, broken symlink, and canonical duplicate are candidates | Type and containment authorization runs                  | Only the canonical non-symlink regular file can be returned; aliases/unsupported entries are omitted, duplicates collapse, and no rejected name, target, or metadata is disclosed.       |
| R2-DSC-007 | Multi-root Extension Host        | Parent and nested workspace roots contain candidates, including aliases and identical relative names                                                                  | Either folder is listed/searched                         | The deepest canonical root owns each file exactly once; the parent call does not expose nested-root-owned entries.                                                                       |
| R2-DSC-008 | Extension host                   | Candidate enumeration order changes across runs while authorized content is unchanged                                                                                 | Results are produced repeatedly                          | Paths use normalized forward slashes, canonical duplicates are removed, and Unicode code-point ordinal ordering and cursors are byte-for-byte deterministic apart from observation time. |
| R2-DSC-009 | Extension host                   | An entry changes type, target, ownership, size, or existence after discovery                                                                                          | Authorization/read/result assembly continues             | The entry is rechecked and omitted; no stale content or rejected path metadata is returned.                                                                                              |
| R2-DSC-010 | Extension and server integration | Unsupported entries carry unique filename/path/target canaries                                                                                                        | Success, warning, and error paths complete               | Only bounded aggregate warning/count data crosses IPC/MCP or logs; no canary is present.                                                                                                 |

## `search_workspace_text`

| ID         | Test boundary                     | Given                                                                                                                                                         | When                                                          | Then                                                                                                                                                                         |
| ---------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R2-SRC-001 | Protocol unit                     | Empty, untrimmed, NUL-containing, 256-scalar, and 257-scalar queries are supplied                                                                             | Schemas validate them                                         | Only the documented literal query domain is accepted; regex flags/pattern modes do not exist.                                                                                |
| R2-SRC-002 | Extension unit                    | Queries contain regex metacharacters, backslashes, glob characters, and command-like text                                                                     | Matching runs                                                 | Every character is treated as inert literal data; no regex compilation, command execution, interpolation, or content evaluation occurs.                                      |
| R2-SRC-003 | Extension unit                    | ASCII, non-ASCII, combining, surrogate-pair, CRLF, case variants, and word-boundary fixtures are searched                                                     | Case-sensitive, Unicode ignore-case, and whole-word modes run | Returned ranges are exact zero-based UTF-16 half-open ranges and whole-word behavior follows the contract's fixed Unicode categories rather than editor/language settings.   |
| R2-SRC-004 | Extension host                    | A discovered canonical file has a clean or dirty open document whose text differs from disk                                                                   | Search runs                                                   | Live text wins, matches report live version/dirty state, and stale disk-only matches are absent.                                                                             |
| R2-SRC-005 | Extension host                    | An open document is untitled, virtual, external, symlink-only, deleted-only, excluded, or not among discovered canonical candidates                           | Search runs                                                   | Its live text is not overlaid and none of its identity or canary content is disclosed.                                                                                       |
| R2-SRC-006 | Extension host                    | Closed files are exactly 2 MiB and one byte larger, contain NUL in the probe, contain invalid UTF-8, are empty, or are non-regular                            | Search runs                                                   | Valid boundary/empty text is handled; oversized/binary/invalid/unsupported entries are omitted before unbounded decode/match work and produce only aggregate warnings.       |
| R2-SRC-007 | Extension host                    | A closed file changes size/mtime, is replaced, or disappears between selection, read, and post-read verification                                              | Search runs                                                   | No match, partial text, stale state, or path metadata from that candidate is returned; mutation is reported only through the bounded aggregate warning.                      |
| R2-SRC-008 | Scheduler unit and Extension Host | Multiple simultaneous searches each have many closed candidates                                                                                               | Reads are delayed and observed                                | All searches share one per-window scheduler, peak closed-file reads never exceeds two, and request-level four/eight admission ceilings are not bypassed.                     |
| R2-SRC-009 | Scheduler/IPC integration         | Cancellation, timeout, disconnect, trust loss, or disablement occurs during discovery, between batches, during a live scan, and during a non-cancellable read | The request settles                                           | No new batch starts after invalidation; client outcome occurs at most once; late values are discarded; active non-cancellable work remains counted until actual settlement.  |
| R2-SRC-010 | Extension unit and host           | Candidate, per-file, aggregate-byte, match, context, response-byte, and five-second time ceilings are independently exceeded                                  | Search runs                                                   | Each dimension stops further applicable work at its own bound, produces canonical explicit incompleteness, and never raises another ceiling as compensation.                 |
| R2-SRC-011 | Output-hardening unit             | Match locations fit but optional context would cross per-snippet, aggregate-context, or serialized-result limits                                              | Results are reduced                                           | Context is shortened/omitted before any match location, `CONTENT_TRUNCATED` is explicit, highlight ranges remain valid, and no partial invalid UTF-8/code point is returned. |
| R2-SRC-012 | Extension host                    | Enumeration order and read completion order vary while files remain unchanged                                                                                 | Search repeats                                                | Documents sort by relative path and matches by range, grouping preserves global order, and result/cursor ordering is deterministic.                                          |

## Gate

The read/discovery security gate closes only when:

1. ADR 0005, the v0.2 read security model, these criteria, and the selected contract
   shapes remain synchronized;
2. every applicable row has a repeatable automated assertion at its stated boundary;
3. source and packaged-pair tests pass on supported macOS and Linux;
4. a post-implementation security review finds no unresolved high-severity issue; and
5. measured implemented behavior remains within the accepted resource and agent-
   efficiency envelope.

This gate authorizes only the three read-only tools. Write authorization and mutation
remain governed by proposed ADR 0004 and separate future acceptance criteria.
