# Milestone 1 security acceptance criteria

> These are the inherited read/transport criteria. The active complete-product gate is
> [`security-acceptance-criteria-v1.0-full-ide.md`](./security-acceptance-criteria-v1.0-full-ide.md).

- Status: Accepted
- Date: 2026-07-10
- Scope: Milestone 1 secure IPC vertical slice

## Purpose

This document defines the security behavior that the Milestone 1 implementation and its
automated tests MUST satisfy. `Accepted` means that these criteria are the agreed
contract; it does not mean that the implementation or tests already exist.

The criteria apply together with ADR 0002, the security model, and the v0.1 tool
contract. A Milestone 1 implementation does not pass the security gate unless every
applicable criterion below has an automated test at the indicated boundary. A deferred
platform criterion MUST remain visibly skipped with its gate documented; it MUST NOT be
reported as passing.

## Frozen test constants and conventions

`KiB` and `MiB` mean 1,024 and 1,048,576 bytes respectively. Byte ceilings are
inclusive: a payload exactly at the ceiling is accepted if it is otherwise valid, and a
payload one byte larger is rejected.

| Contract item                     |                             Accepted value |
| --------------------------------- | -----------------------------------------: |
| IPC protocol                      | JSON-RPC 2.0 over `Content-Length` framing |
| Maximum IPC header block          |                                      8 KiB |
| Bridge-to-extension JSON-RPC body |                                    256 KiB |
| Extension-to-bridge JSON-RPC body |                                      2 MiB |
| Registry record                   |                                     64 KiB |
| Serialized MCP tool input         |                                    256 KiB |
| Serialized MCP success result     |                                    512 KiB |
| Handshake timeout                 |                                  3 seconds |
| Registry endpoint-probe timeout   |                                  3 seconds |
| Registry heartbeat interval       |                                  5 seconds |
| Registry stale threshold          |                                 60 seconds |
| Connections per VS Code window    |                                          4 |
| Active calls per connection       |                                          4 |
| Active calls per VS Code window   |                                          8 |
| Queued calls per VS Code window   |                                         16 |
| Simple-operation timeout          |                                  5 seconds |
| Language-provider timeout         |                                 15 seconds |

The IPC header ceiling includes the terminating `\r\n\r\n`. The body ceilings count the
exact UTF-8 byte length named by `Content-Length`. A frame has exactly one non-negative
decimal `Content-Length`; duplicate, signed, fractional, hexadecimal, or otherwise
malformed values are invalid.

MCP input size is measured from the serialized tool arguments before an IPC request is
created. MCP success-result size is measured from the complete serialized success value
returned to the MCP SDK, including contract metadata and warnings. Result truncation
MUST happen before that value crosses the 512 KiB ceiling and MUST remain explicit.

JSON-RPC request IDs are non-negative JavaScript safe integers in the inclusive range
`0` through `Number.MAX_SAFE_INTEGER`, matching the selected `vscode-jsonrpc` usage.
Strings, negative numbers, fractions, unsafe integers, `null`, and booleans are not
valid request IDs for request messages. Notifications do not carry an ID.

The supported environment is a standard local VS Code Desktop installation on the
operating systems declared supported by the release. Remote extension hosts, VS Code for
the Web, virtual workspaces, Snap, and Flatpak are deferred. Deferred environments fail
closed and do not publish an instance. Version 0.1 has no persistent instance alias; an
instance ID is opaque and valid only for its VS Code-window lifetime.

## Milestone gate

Milestone 1 satisfies this document when the 1.0-applicable rows have executable,
repeatable assertions at the stated boundary and all supported macOS/Linux platform
checks pass. Test fixtures MUST use synthetic paths and secrets. A skipped applicable
negative-path, permissions, timeout, cancellation, or no-network test is an unmet gate
rather than an implicit pass. Future Windows rows become applicable only through a new
accepted support-scope decision.
